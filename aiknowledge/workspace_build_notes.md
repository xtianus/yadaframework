## Eclipse metadata generation

- Eclipse metadata (`.project`, `.classpath`, `.settings/`) is git-ignored in every module and is meant to be regenerated with `.\gradlew eclipse` from the module directory. Running it from one module also regenerates the modules that its `settings.gradle` includes, so the last run wins for shared projects.
- All Java modules apply `YadaWeb/eclipseSetup.gradle` right after `loadSharedProperties.gradle` (after `apply plugin: 'eclipse'` in `YadaTools`). That script is the single place where Eclipse JDT compliance, the `JavaSE-<java_version>` JRE container, the WTP `jst.java` facet version, and the Buildship nature/builder are defined, all driven by `java_version` from `YadaWeb/shared.gradle.properties`.
- The Gradle `eclipse` tasks merge into the files already on disk instead of replacing them, so obsolete entries survive a regeneration. In particular a stale `jst.java` facet of an older version stays next to the new one, and the WTP java facet version overrides the JDT settings, which silently downgrades the project compiler level and the JRE container. `eclipseSetup.gradle` removes `jst.java` facets whose version differs from `java_version` and de-duplicates facets, natures and build commands on merge.
- Buildship's *Refresh Gradle Project* never runs the `eclipseWtpFacet`/`eclipseWtpComponent` tasks, so it cannot repair a wrong facet version, and it skips projects whose `.project` lacks `org.eclipse.buildship.core.gradleprojectnature`. Use `.\gradlew cleanEclipse` followed by `.\gradlew eclipse` (two separate invocations, because task ordering within a single one is not guaranteed) when the metadata is inconsistent.
- `.settings/org.eclipse.buildship.core.prefs` is written by Buildship, not by Gradle, and is not regenerated by `cleanEclipse`/`eclipse`. Buildship requires the `connection.project.dir` key: when it is missing the project gets the marker *Invalid Gradle project configuration file*. The value is the relative path from the project directory to the root of the Gradle build that owns the project: empty when the module is its own root build, `../../ldm-site/LdmSite` for `YadaWeb` and `YadaWebSecurity` when they are imported as part of the `LdmSite` build.
