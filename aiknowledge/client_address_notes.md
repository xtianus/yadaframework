# Client address and X-Forwarded-For

- The client address is `request.getRemoteAddr()`. `YadaClientAddress.resolve(remoteAddr, xForwardedForValues, trustedProxies)` (YadaWeb, `net.yadaframework.components`) is the only place that reads forwarded text; it is used by `AuditFilter` and `YadaWebUtil.getClientAddress`.
- `<security><trustedProxies><proxy>` (`YadaConfiguration.getTrustedProxies()`, default empty) lists the IP addresses of proxies allowed to set `X-Forwarded-For`. Entries that are not IP literals (`*`, host names, CIDR ranges) are ignored: trusting everybody is impossible. Addresses are compared in canonical form (`::1` equals `0:0:0:0:0:0:0:1`, IPv4-mapped IPv6 equals IPv4).
- The header is considered only if the immediate peer is a trusted proxy. The chain (all header lines joined) is read from the right: trusted hops are skipped, the first untrusted hop is the client. A hop that is not an IP literal (text, port, brackets, control characters) makes the peer address the result. A chain made only of trusted proxies also gives the peer.
- `AuditFilter` MDC: `remoteIp` is the resolved address (or `?`); `forwardedFor` is the raw header, sanitized with `YadaClientAddress.sanitizeForLog` (control characters become `?`, 200 characters maximum) and present only when the header was sent. It is for diagnostics: never use it as an address. `AuditFilter.getTrustedProxies()` is protected so a subclass can fix the list in tests.
- `YadaWebUtil.getClientIp` (deprecated) returns the same address as `getClientAddress`, or `?`; it no longer returns `[for ...]` text.
- Deployments behind an ingress should use Tomcat `RemoteIpValve` with exact `internalProxies`/`trustedProxies`, and the ingress must overwrite the forwarded headers; then no framework setting is needed. See `YadaDocs` security overview, "Client address behind a reverse proxy".
- The only in-framework caller of `getClientIp` is `YadaEmailService.sendSupportRequest` (the address shown in the support email). Nothing in the framework uses the address for rate limiting, lockout or geolocation.
- Tests: `YadaClientAddressTest`, `AuditFilterSecurityTest` (unit) and `net.yadaframework.tests.web.audit` (integration, direct and configured proxy: `run.setConfigurationValue("security/trustedProxies/proxy", "127.0.0.1", "::1")`).
